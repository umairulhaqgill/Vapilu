# TTS Service

Turns text into streamed speech, using **Piper** - a free, local, offline
neural TTS engine. No API key, no per-character cost, nothing leaves your
machine.

## A quick note on quality vs. cloud options

Piper is fast and completely free, but it sounds noticeably more synthetic
than cloud options like ElevenLabs or Cartesia. That's a real, known
trade-off - not a bug. If "feels human" becomes the top priority later,
swapping to a cloud provider only means rewriting `tts_client.py` (same
pattern as every other service here) - `tts_service.py` and everything that
calls it stays the same.

## Why it's structured this way

`tts_client.py` is the only file that knows Piper is involved - same pattern
as `stt_client.py` and `nlu_client.py`. One important detail baked in:
Piper's synthesis is synchronous, CPU-bound work with no idea asyncio
exists. Calling it directly inside an async function would freeze the
entire service for every other concurrent call while one utterance
synthesizes. `synthesize_stream()` runs the real work on a background
thread and feeds chunks back to the async caller safely - this was tested
directly (not just read-and-trust) by confirming the event loop keeps
processing other work while synthesis runs.

## Setup

```
python -m pip install -r requirements.txt
cp .env.example .env
```

### Download a voice model (one-time)

Piper's voice models aren't bundled with the package - download one:

```
python -m piper.download_voices en_US-amy-medium --download-dir voices
```

This creates `voices/en_US-amy-medium.onnx` and its matching `.onnx.json`
config file. Browse other available voices (different languages/accents/
quality tiers) at: https://github.com/OHF-voice/piper1-gpl/blob/main/VOICES.md

Then fill in `.env`:
- `PIPER_MODEL_PATH=voices/en_US-amy-medium.onnx` (or whichever voice you downloaded)
- `TTS_SERVICE_TOKEN` - a new random string, different from your other services' tokens

## Test it - two ways

**1. Simplest possible test** (no service, just Piper directly, plays through your speakers):
```
python test_local_playback.py
```

**2. Real test, over the actual WebSocket** (matches how the Orchestrator will use it):
```
uvicorn tts_service:app --reload --port 8003
```
then, in another terminal:
```
python test_stream_client.py
```

Both should play back a spoken sentence through your speakers.

## API contract (short version)

```
ws://<host>:8003/ws/synthesize?token=<token>

Server sends once, immediately on connect:
  {"event": "format", "sample_rate": ..., "sample_width": 2, "channels": 1}

Client sends: one text message per utterance (e.g. one sentence)

Server streams back:
  - binary WebSocket frames: raw 16-bit PCM audio chunks, as they're generated
  - {"event": "utterance_end"}   - once that utterance's audio is complete
  - {"error": "...", "detail": "..."}   - if synthesis failed
```

Connection stays open - send another text message for the next utterance
without reconnecting.

## What's next

This is the last piece from the original roadmap. Wiring it into the
Orchestrator means: instead of sending `bot_speech_chunk`/`bot_speech_end`
text events to the caller, the Orchestrator accumulates NLU text deltas
into complete sentences (using punctuation as a boundary), sends each
finished sentence to this service, and streams the resulting audio back
to the caller - so speech starts on the first sentence while later
sentences are still being generated by the LLM.
